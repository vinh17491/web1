01 / PROBLEM

MULTIPLE ROLES. ONE AUTHORITY.

GymFit combines public catalog flows with authenticated Member, Coach and Admin workflows. The challenge is keeping authorization, ownership, inventory and order/payment state correct across all three surfaces.

The frontend can hide a route. It cannot grant permission. Controllers derive actor identity from authenticated request context and ownership queries remain authoritative at the API boundary.

02 / SECURITY

JWT WAS NOT TREATED AS “LOGIN SOLVED.”

The hardened flow validates signature, issuer, audience, user/session state, token version and live role before authorization. Refresh credentials are opaque random values stored only as SHA-256 hashes.

ACCESS TOKEN → signature / issuer / audience → live AuthSession → user token_version / role / active state → route role check → ownership query REFRESH TOKEN → opaque credential → SHA-256 hash in DB → atomic rotation → replay detection → token-family revocation
REVOCATION

Logout has server-side meaning.

Logout and security changes revoke sessions instead of relying only on access-token expiry.

IDOR

Ownership is tested, not assumed.

Acceptance differentiates Member A/B and Coach A/B to test self and assigned scope across accounts.

FRONTEND

Route guards are UX.

Protected navigation improves experience, but never replaces backend role and ownership checks.

FAILURE PATH

Replay becomes evidence.

Refresh-token reuse triggers family revocation instead of silently issuing another credential.

03 / COMMERCE

INVENTORY IS AN INVARIANT.

Catalog data separates Products and ProductVariants. Inventory is tracked at variant level, because the purchasable SKU is what actually owns stock.

available = on_hand - reserved Product → Variant → Cart → Checkout → Order ↓ Reservation ↓ Payment ↓ Fulfillment Order: PENDING → CONFIRMED → PROCESSING → SHIPPED → DELIVERED Payment: UNPAID → PENDING → PAID / FAILED → REFUNDED

Creating an order reserves stock. Valid cancellation or expiration releases the reservation. Delivery reduces both reserved and on-hand quantity. Order and payment history preserve actor, transition and time.

05 / LIMITATIONS

WHAT I WOULD NOT CLAIM.

Bank settlement/refunds are manual records rather than Stripe or direct bank settlement APIs. Some legacy modules retain mixed controller/service patterns. Strict CSP, exact CORS allowlists and a future cookie-based auth design remain improvement areas.

The project is still in progress. The audited baseline did not represent the later workout-program scope as complete. That boundary matters more than making the portfolio sound bigger.
